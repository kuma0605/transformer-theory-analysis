# 注意力是怎么工作的 · 零基础版

一个单页交互式讲解：用「北京 的 天气 怎么样」这一个例句，把 Transformer 的注意力机制从分词一路拆到加权求和。

面向**没有 AI 基础**的读者。读完能用自己的话说明一件事：模型读到「怎么样」时，为什么会去看「天气」，而不是句子里的其他词。

- 只需要会加减乘除，不需要编程基础、微积分或英文论文
- 主线一路点「下一步」即可读完，折叠起来的延伸内容可以跳过
- 文中每个数字都能自己验算，没有一处是凭空写上去的

## 快速开始

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

其他命令：`pnpm build` 生产构建，`pnpm start` 启动构建产物，`pnpm lint` 代码检查。

## 内容结构

主线 8 屏，靠顶部圆点或底部按钮切换：

| 屏 | 内容 |
| --- | --- |
| 开始之前 | 阅读门槛、四个术语（模型 / token / 词向量 / 注意力） |
| 第 1 步 | 输入一句话，切分成 token |
| 第 2 步 | 每个词转换成词向量；用招聘类比引出为什么需要三种向量 |
| 第 3 步 | 每个词生成 Q、K、V |
| 第 4 步 | Q 与每个 K 做点积，得到相关度分数 |
| 第 5 步 | Softmax 把分数换算成注意力权重 |
| 第 6 步 | 按权重合并 V，得到最终表示 |
| 回顾 | 六步串讲，外加 KV Cache 与显存 |

折叠区分两档。**延伸**帮助理解主线，随时可看；**进阶**是 KV Cache、GQA 这类工程内容，跳过不影响主线。其中四块是独立的交互组件：

- `MatrixExplain`（第 3 步）— 选一个词、选一个矩阵，逐行看「乘以矩阵」到底在算什么
- `Training`（第 3 步）— 手动训练一格权重，观察注意力分布如何被「答错」一次次推上去
- `WhyThree`（第 2 步）— 用可点的对称矩阵和两组滑块，说明为什么不能只用一个或两个向量
- `MultiHeadLayer`（第 6 步）— 跟踪「她」这个词，看它如何在 32 层里逐层锁定「小红」

## 数值全部同源

这份讲解承诺「文中的数字都可以自己验算」，因此**所有展示的数值都从同一组常量推导**，没有任何手写的示意数字。改动时请保持这条约束。

```
VEC  ──┬─► SYM（WhyThree 的对称矩阵）
       │
       └─► project(v, Wq/Wk) ──► Q_HOW / K_AFTER
                                      │
                                      └─► ATTN_SCORES ──► ATTN_WEIGHTS
                                                     └──► SCALED_WEIGHTS（除以 √d 的对照）
```

几处容易踩的地方：

- `MATS` 必须定义在 `Q_HOW` / `K_AFTER` 之前，否则模块初始化时会触发 TDZ 报错
- `Wq` 与 `Wk` 的**同一行必须问同一个话题**（Q 问「我在找 X 吗」，K 答「我是 X 吗」），否则点积的第 r 项就成了拿两件不相干的事情相乘
- 正文里引用的具体数值（如「天气」的分数、矩阵演示末尾的三个数）一律用表达式渲染，不要写死

当前这组常量算出的结果：相关度分数 `北京 0.53 / 的 −0.33 / 天气 1.25 / 怎么样 0.56`，对应权重 `22% / 9% / 46% / 23%`。「的」是虚词，分数为负，正好呼应第 4 步讲的「异号相乘为负」。

## 文案约定

- 引号统一用 `“”`，需要嵌套时内层用 `‘’`
- 指代例句里的**词**时一律加引号（“天气”约 46%、“北京”约 22%）；指代它所表示的**概念**时不加（“怎么样”问的是天气的状态，而不是北京的位置）。同一句里若有几个词并列，必须全部加，不能只给“的”“怎么样”这类看着别扭的加
- 折叠标题只有两种前缀：`延伸：……` 和 `进阶：……（可跳过）`
- 破折号统一为 `——`，前后不加空格
- 术语固定：词的数字表示一律称**词向量**；打分链路是**相关度分数**（点积结果）→ **注意力权重**（Softmax 之后）
- 「权重」有两个所指，同屏出现时必须写清是哪个：Wq/Wk/Wv 矩阵里待训练的数字（模型参数），以及 Softmax 输出的**注意力权重**（百分比）。`Training` 组件讲的是前者，但它下方就画着后者的柱状图，改这一段时尤其要留意
- 描述打分范围时要写「前面的词**和它自己**」，不能写成「前面每个词」——第 4 步实际算了四个分数，「怎么样」自己也在其中（0.56 分、23% 权重）
- 用规范书面语，一句只说一件事；类比（招聘、成绩单、旋钮）保留，但叙述用第三人称陈述
- 折叠区里的组件不要引用后面步骤的编号。`Training`、`MatrixExplain` 都挂在第 3 步下，读者此时还没读到第 4、5 步，需要提到时得把内容讲清楚，或写明「后面第 N 步会讲」
- 灰阶分三档，不可倒挂：面板标题 `#333` + `fontWeight 600`（`Label` 组件），正文与说明 `#555`（`Muted` 组件），坐标轴与占位符 `#6e6e6e` 至 `#767676`。`#888` 及更浅的灰在白底上对比度不足 3.5:1，小字号下尤其难读
- 加深正文时要连带检查它上方的标题。正文一旦深于标题，层次就反了，读者会先看到说明再看到标题

## 项目结构

```
app/
  page.tsx       全部内容与交互都在这里（约 1500 行，无外部 UI 依赖）
  layout.tsx     元数据、图标、Analytics
  globals.css    Tailwind 入口与基础样式
components/ui/   脚手架残留，页面未使用
lib/             脚手架残留，页面未使用
```

`page.tsx` 自成一体：顶部是 `STEPS` 数组（每屏一项），中部是四个交互组件，底部是 `Card` / `Detail` / `Muted` 等展示原语。配色和排版走内联样式，没有引入组件库。

## 有意做的简化

为了照顾零基础读者，以下内容被简化或略过，阅读源码时请注意它们与真实模型的差距：

- 词向量取 4 维（真实模型 4096 维），Q/K 取 3 维，都是为了能手算
- 按整词切分 token，真实模型通常切得更细
- 位置编码只提了一句「由另一套机制记录」，没有展开
- 第 5 步正文省略了 Softmax 前除以 √d 的一步，单独放在折叠区讲
- 多头合并后的输出投影、前馈层、层归一化均未涉及
- 矩阵每一行的「问题名称」是为讲解而起的，真实模型的权重没有语义标签
